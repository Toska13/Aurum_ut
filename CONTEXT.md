# Aurum UT — контроль цепочки заказа

Общий язык для цепочки «заказ клиента → закупка → склад → отгрузка → оплаты». Только доменные термины — без имён модулей, регистров и UI-реализации.

## Цепочка и потребители

**Цепочка заказа**:
Все документы и движения, которые можно связать с одним заказом клиента: сборка, закупка, приёмка, маркировка, реализация, ордера, оплаты.
_Avoid_: цепочка документов, подчинённость, структура подчинённости

**Монитор цепочки**:
Экран по одному заказу клиента: дерево в табличном документе от заказа клиента через позиции (с колонками показателей) к документам и штрихкодам упаковок. Не набор таблиц на форме.
_Avoid_: форма подробной информации, дашборд, таблица формы

**Отчёт по цепочкам**:
Иерархическое дерево: заказ клиента → позиции заказа → связанные документы позиции (заказы поставщику, заказы на сборку и дальше по цепочке). На каждом уровне — те же показатели, что собирает контроль цепочки. Для детального разбора одного заказа — монитор.
_Avoid_: плоский список, сводный отчёт, аналитика

**Кэш цепочки**:
Сохранённый результат последнего полного пересчёта по заказу. Если кэш актуален и пересчёт не требуется — показываем из кэша; иначе полный пересбор → запись в кэш → выдача.
_Avoid_: снимок, материализация (в разговоре с пользователем)

## Позиция и количества

**Позиция заказа**:
Единица учёта в цепочке: номенклатура + характеристика + назначение (назначение — с шапки заказа клиента). Две одинаковые неотменённые строки в табличной части заказа — одна позиция, количества суммируются.
_Avoid_: строка заказа, зерно, SKU, номер строки

**Отменённая позиция**:
Строка заказа клиента с признаком отмены не попадает в монитор и отчёт — позиция не показывается.
_Avoid_: скрытая строка, неактивная

**Показатели позиции (товары)**:
Каждый этап цепочки — отдельная колонка, без свёртки в одну «отгружено» или «закуплено». По отгрузке: реализация и расходные ордера — раздельно. По закупке: приобретение и приходные ордера — раздельно. Приоритет интерпретации: товарные колонки важнее денежных.
_Avoid_: факты, метрики, KPI, итого отгружено

**Остаток на складе**:
Остаток по регистру запасов для номенклатуры и характеристики позиции. Если у заказа клиента не заполнено назначение — остаток считается по пустому назначению (товары, закупленные без назначения, тоже видны). Если назначение заполнено — отбор по нему.
_Avoid_: принято минус отгружено, складской баланс

**Несколько заказов поставщику на одну позицию**:
Допустимо; в таблице позиции — сумма по всем заказам поставщику, в дереве — каждый заказ поставщику отдельным узлом.
_Avoid_: дублирование позиции, split

**Штрихкод упаковки**:
Отдельная таблица фактов: принято, отгружено, остаток по коду маркировки; не подменяет колонки количества по позиции.
_Avoid_: КМ, маркировка (как замена колонок заказа)

## Деньги

**Шифр**:
Первые 10 символов строкового представления характеристики; ключ для привязки оплат и статей бюджета к позиции. Не отдельный справочник и не произвольный код.
_Avoid_: код позиции, код характеристики, артикул

**Показатели позиции (деньги)**:
Заявлено к оплате, оплачено, поступило от клиента — второй слой после товарных колонок. Сверка с регистрами взаиморасчётов — индикатор, не главный смысл экрана. Накладная не приравнивается к ордеру; заявка — к списанию.
_Avoid_: бюджет, статьи бюджета (как термин экрана)

## Проблемы и контроль

**Проблема цепочки**:
Отклонение от ожидаемого состояния позиции или связи документов. Матрица «критично / предупреждение» — после внедрения основного функционала, по обратной связи пользователей; на первом этапе — все собранные показатели без единой раскраски.
_Avoid_: ошибка, алерт, инцидент

**Сирота**:
Документ, который по правилам цепочки не удалось привязать к текущему заказу клиента. Показывается отдельной веткой «Не связанные» и поднимает общий флаг «есть сироты».
_Avoid_: не связанный, orphan, потерянный документ

**Контроль ввода**:
Сначала только предупреждение (без запрета записи). Жёсткая блокировка — поэтапно: (1) лишний заказ на сборку, (2) заказ поставщику без связи с заказом клиента или сборкой, (3) расходный ордер без ссылки на реализацию.
_Avoid_: валидация, проверка заполнения

## Сборка

**Заказ на сборку**:
Отдельная ветка цепочки для комплекта; комплектующие — в таблице заказа на сборку, не смешивать со строкой комплекта в заказе клиента.
_Avoid_: сборка, комплект (без уточнения «заказ на»)

**В сборке (на позиции заказа клиента)**:
Количество комплекта по связанному заказу на сборку (не просто да/нет). После документа сборки товаров это количество **не обнуляется**. Детализация комплектующих — в ветке заказа на сборку, не на строке комплекта в заказе клиента.
_Avoid_: собирается, на сборке, флаг сборки

**Собрано (на позиции заказа клиента)**:
Количество комплекта по проведённым документам сборки товаров (шапка документа). Отдельная колонка от «в сборке».
_Avoid_: собрано ордером, отгружено, свернуто в «в сборке»

**Путь позиции**:
На строке заказа клиента заполняется **либо** пара закупки («заказано поставщику» / «приобретено»), **либо** пара сборки («в сборке» / «собрано») — по тому, есть ли заказ на сборку на это зерно. «Заказано поставщику» после приобретения не обнуляется. Закупка комплектующих не показывается на строке комплекта.
_Avoid_: смешанные колонки обоих путей на одной строке комплекта
