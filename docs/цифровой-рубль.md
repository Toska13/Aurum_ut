# Цифровой рубль в УТ

Исследование типовой конфигурации Управление торговлей.  
Дата: 2026-09-03.

## Вывод

Цифровой рубль есть **только в типовой УТ**. Это не отдельная подсистема и не отдельный документ, а специальный вид элемента справочника банковских счетов.

Отдельного обмена с платформой ЦБ (API кошелька) в конфигурации нет. DirectBank на БИК платформы не настраивается. Учёт, проверки корреспонденции и печать — да; отправка в платформу — через обслуживающий банк вне этой галочки.

## Что это такое

Галочка `СчетЦифровогоРубля` — признак **кошелька на платформе цифрового рубля ЦБ**, а не ещё одно поле обычного расчётного счёта.

- Платформа ЦБ: БИК `044595002` (`ОбменСБанкамиСлужебный.БИКПлатформыЦифровогоРубля()`).
- Тип счёта в перечислении всё равно `Расчетный`. Отдельного значения в `Перечисление.ТипыБанковскихСчетов` нет (там только Расчетный, Транзитный, Депозитный, ЗарплатныйПроект, Прочий, Казначейский).
- Создаётся не галочкой на обычной форме, а отдельным сценарием «создать счёт цифрового рубля».

## Модель данных

Оба справочника:

- `Справочник.БанковскиеСчетаОрганизаций`
- `Справочник.БанковскиеСчетаКонтрагентов`

| Реквизит | Тип | Смысл |
|---|---|---|
| `СчетЦифровогоРубля` | Булево | Признак кошелька ЦР |
| `ИдентификаторСчетаЦифровогоРубля` | Строка | Идентификатор кошелька на платформе (вместо 20-значного номера счёта) |

## Карточка и создание

Создание: `ДенежныеСредстваКлиентЛокализация.ОткрытьСозданиеБанковскогоСчетаЗавершение`.

- ставится `СчетЦифровогоРубля = Истина`;
- для организации дополнительно `ТипСчета = Расчетный`;
- открывается форма `ФормаЭлементаСчетЦифровогоРубля`.

Открытие уже записанного элемента — `ОбработкаПолученияФормы` менеджера справочника:

- флаг включён → `ФормаЭлементаСчетЦифровогоРубля`;
- флаг выключен → обычная `ФормаЭлемента`.

Автонаименование: `Счет цифрового рубля *XXXX` (последние 4 символа идентификатора).  
Дубли ищутся по `ИдентификаторСчетаЦифровогоРубля`, не по `НомерСчета`.

Настройки полей отдельной формы: `НастройкиПолейФормыСчетаЦифровогоРубля()` в менеджерах обоих справочников. Корреспондентский счёт на карточке ЦР не показывается (`ДенежныеСредстваКлиентСервер.ЗаполнитьОсновныеРеквизитыБанка` пропускает коррсчёт, если `СчетЦифровогоРубля`).

## Чем счёт с галочкой отличается от обычного

| | Обычный счёт | Счёт ЦР |
|---|---|---|
| Номер | `НомерСчета` (20 цифр) | `ИдентификаторСчетаЦифровогоРубля` |
| Наименование | банк + номер | `Счет цифрового рубля *XXXX` |
| Банк | банк из классификатора | платформа ЦР, БИК `044595002` |
| Коррсчёт | есть | не показывается |
| Дубль | по номеру счёта | по идентификатору ЦР |
| DirectBank | настраивается на банк счёта | банк с БИК платформы исключается из настройки |
| Форма элемента | `ФормаЭлемента` | `ФормаЭлементаСчетЦифровогоРубля` |

В платежном поручении и в счетах на оплату / извещениях при галочке в поле «номер счёта» уходит **идентификатор**, не `НомерСчета`. В печатных счетах и извещениях БИК часто пустой.

Автоподбор счёта контрагента (`Справочник.БанковскиеСчетаКонтрагентов.ПолучитьБанковскийСчетПоУмолчанию`) берёт только счета того же характера, что и корреспондирующий (ЦР к ЦР, обычный к обычному).

## Главное правило корреспонденции

Допустима только пара одного характера:

```
(оба ЦР) ИЛИ (оба обычные)
```

Смесь запрещена. Текст ошибки:

> Расчетный счет не может корреспондировать со счетом цифрового рубля. Укажите другой счет

Проверка: `ДенежныеСредстваСерверЛокализация.ПараметрыКорреспонденцииСоСчетомЦифровогорубля` и `ПроверитьКорреспонденциюБанковскихСчетов`.

Та же логика:

- договоры, в том числе эквайринг (`ПроверитьДоговорНаВозможностьКорреспонденцииСоСчетомЦифровогоРубля`);
- заявка на расходование (`ЗаявкаНаРасходованиеДенежныхСредствЛокализация`);
- заявка на командировку (лицевой счёт, `ЗаявкаНаКомандировкуЛокализация`).

Примеры:

- организация ЦР + контрагент ЦР — можно;
- организация ЦР + обычный счёт контрагента — нельзя;
- обычный счёт организации + ЦР контрагента — нельзя.

## Какие операции можно и нельзя

Разрешены (если оба счёта одного характера): оплата поставщику, поступление от клиента, возвраты, бюджет, таможня, зарплата на лицевые / по зарплатному проекту, подотчёт, прочая выдача / поступление, переводы между организациями.

Запрещены даже для пары ЦР↔ЦР:

- наличные (снятие, поступление из кассы);
- депозиты;
- конвертация валюты;
- платёжные карты;
- кредиты;
- займы сотруднику и выданные займы.

Текст:

> Счет цифрового рубля не может быть использован для хозяйственной операции «…». Укажите другой счет

Список запрещённых операций — в `ПроверитьКорреспонденциюБанковскихСчетов` (`ДенежныеСредстваСерверЛокализация`).

## Печать и реквизиты

`СписаниеБезналичныхДенежныхСредствЛокализация.СформироватьПлатежноеПоручение`: если `СчетЦифровогоРубля`, номер счёта плательщика/получателя = `ИдентификаторСчетаЦифровогоРубля`.

Тот же приём в печатных формах счетов на оплату / извещений (заказ клиента, реализация, корректировка, передача и возврат между организациями и др.): номер = идентификатор, БИК часто выводится пустой строкой.

Реквизиты счёта для кода: `ПолучитьРеквизитыБанковскогоСчетаОрганизации` / `ПолучитьРеквизитыБанковскогоСчета` возвращают и флаг, и идентификатор.

## DirectBank

`ОбменСБанкамиСлужебный.БанкиДляНастройкиОбменаЧерезДиректБанк` и помощник создания настройки обмена исключают счета, у которых `Банк.Код = 044595002`. Платформа ЦР не считается банком для DirectBank.

## Ключевые объекты и процедуры

| Место | Роль |
|---|---|
| `Справочник.БанковскиеСчетаОрганизаций` / `БанковскиеСчетаКонтрагентов` | реквизиты и формы ЦР |
| `ФормаЭлементаСчетЦифровогоРубля` | карточка кошелька |
| `ДенежныеСредстваКлиентЛокализация.ОткрытьСозданиеБанковскогоСчетаЗавершение` | сценарий создания |
| `ДенежныеСредстваСерверЛокализация` | корреспонденция, запрет операций |
| `ОбменСБанкамиСлужебный.БИКПлатформыЦифровогоРубля` | константа БИК `044595002` |
| `СписаниеБезналичныхДенежныхСредствЛокализация.СформироватьПлатежноеПоручение` | номер в ПП = идентификатор |
| `ЗаявкаНаРасходованиеДенежныхСредствЛокализация` | проверка счетов в ЗРДС |
| `ЗаявкаНаКомандировкуЛокализация` | проверка лицевого счёта |
| `Справочник.ДоговорыЭквайринга` | проверка заполнения через корреспонденцию ЦР |

Локализационные модули счетов: `БанковскиеСчетаОрганизацийЛокализация`, `БанковскиеСчетаКонтрагентовЛокализация`.

## Чего в проекте нет

- отдельного документа / регистра / подсистемы «Цифровой рубль»;
- значения перечисления «цифровой рубль»;
- собственного API обмена с платформой ЦБ.
